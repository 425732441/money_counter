# 工资实时回血工具产品设计

日期：2026-04-28

## 1. 产品定位

这是一款 **Windows 优先、完全离线、体积小、资源占用少** 的桌面常驻小工具。它把上班时间转化成可见的“回血”反馈：每秒到账、今日已赚、打工进度、摸鱼收益、下班倒计时，并通过轻角色和梗文案提供情绪价值。

产品不是严肃工资计算器，不是 HR 工具，不是效率监控，也不是老板视角的工时管理系统。它的核心价值是让普通上班族在工作日获得即时奖励、自嘲式娱乐和低打扰陪伴。

工作定位：

> 一个办公室安全的打工人回血小工具。

命名方向暂不锁死。品牌需要兼顾“轻梗体面”和“打工人自嘲”，可以探索“回血、班味、工位续命、薪动、牛马”等语义。其中“牛马”可以作为高传播主题和内容资产，不一定作为主品牌。

## 2. 目标用户

第一目标用户是使用 Windows 办公电脑的普通上班族。他们长时间坐在电脑前，能接受轻度打工人自嘲，希望工作时有一点即时反馈、陪伴感和可分享的情绪出口。

产品必须适合办公室环境：

- 视觉存在感可控。
- 资源占用低。
- 隐私显示可配置。
- 不强制账号。
- 不上传薪资。
- 不读取窗口、键盘输入或浏览记录。
- 不让用户担心它在“监控工作”。

## 3. 推荐路线

推荐路线：

> Windows 离线托盘工具 + 轻角色 + 分享卡片生成 + 弱引流落地页。

已比较的备选路线：

- H5 分享计算器先行：传播最快，但不能验证“上班时常驻”的核心体验。
- 重桌宠/工位搭子：IP 和主题变现空间更强，但 MVP 容易失控。
- 浏览器插件或手机小组件：后续可作为触点扩展，但不适合作为第一主端。

第一版聚焦 Windows。macOS 在核心体验、分享链路和留存验证后进入 Phase 2。

## 4. 用户旅程

1. 首次配置：用户选择收入类型、金额、工作制、隐私显示和默认主题。
2. 上班启动：到上班时间后半自动进入开工状态，也允许用户手动开工。
3. 常驻查看：托盘或小面板展示今日已赚、每秒到账、进度或隐私替代表达。
4. 摸鱼/休息：用户可切换摸鱼、午休、暂停，触发调侃文案并累计摸鱼收益。
5. 日常提醒：低频触发喝水、站立、上厕所、眨眼、午休、快下班提醒。
6. 收工时刻：提示收工，并引导生成今日战报或下班生存卡。
7. 分享引流：用户保存或复制分享图，图片带弱产品标识，把新用户引到官网或 H5 体验页。

## 5. MVP 范围

### 必须有

- Windows 桌面端。
- 系统托盘入口和主面板。
- 首次设置向导。
- 完全离线可用。
- 本地保存配置。
- 收入模式：月薪、时薪、日薪。
- 工作制：标准单班制、弹性工作制、单双休/大小周、自定义每周工作日。
- 状态系统：自动、开工、摸鱼、午休、暂停、收工。
- 手动状态覆盖。
- 隐私显示：真实金额、模糊金额、进度百分比、暗号模式。
- 低频提醒系统。
- 本地轻成就。
- 轻角色及简单状态动画。
- 三个分享模板：今日打工战报、摸鱼回血账单、下班生存卡。
- 保存图片、复制图片。
- 分享图弱引流标识。
- 一键清空本地数据。

### 视工期加入

- 可选悬浮小窗。
- 本地统计开关。
- 开机自启开关。
- 用户主动触发的本地诊断/反馈导出。

### MVP 明确不做

- 账号系统。
- 云同步。
- 强制埋点。
- 在线会员系统。
- 个税、五险一金、绩效、奖金、请假等工资条级计算。
- 活跃窗口识别。
- 键盘输入监听。
- 浏览记录读取。
- 效率评分。
- 复杂桌宠养成、等级、换装。
- 在线主题市场。
- 在线热更新。

## 6. 计算规则

计算模型要做到“娱乐为主，但不要离谱”。

月薪模式：

```text
每秒收入 = 月薪 / 每月工作日 / 每日有效工作秒数
```

时薪模式：

```text
每秒收入 = 时薪 / 3600
```

日薪模式：

```text
每秒收入 = 日薪 / 每日有效工作秒数
```

衍生结果：

```text
今日已赚 = 今日有效计薪秒数 * 每秒收入
摸鱼收益 = 摸鱼状态内计薪秒数 * 每秒收入
今日预计 = 今日计划有效工作秒数 * 每秒收入
```

所有金额都应在产品语义上表达为“估算、回血、到账速度”，避免暗示工资条级准确性。

## 7. 状态机

状态定义：

- 自动：根据工作制和当前时间判断状态。
- 开工：计薪，计入今日已赚。
- 摸鱼：计薪，计入今日已赚，同时单独累计摸鱼收益。
- 午休：默认不计薪，后续可配置。
- 暂停：临时停止计薪，不归入摸鱼。
- 收工：停止今日计薪，进入战报/分享时刻。

手动状态优先于自动规则。到下一个明确时间节点，或用户点击“恢复自动”后，系统重新回到自动判断。

必须覆盖的边界：

- 跨天重置。
- 系统睡眠和唤醒。
- 系统时间变化。
- 周末和自定义工作日。
- 弹性工作制目标工时达成。
- 午休开始和结束。

## 8. 隐私设计

产品必须默认假设薪资数据敏感。

显示模式：

- 真实金额：`¥54.26`、`¥0.02/s`。
- 模糊金额：`¥5x.xx`、`约 ¥50+`，推荐默认。
- 进度百分比：`今日进度 42%`、`已工作 2h`。
- 暗号模式：`咖啡 +2.3 杯`、`奶茶 +1.1 杯`、`回血值 +54`。

托盘、主面板、悬浮小窗、提醒和分享图应尽量支持分别配置。默认建议使用模糊金额。

数据政策：

- 配置只保存在本地。
- 历史统计默认关闭。
- 本地统计必须由用户主动开启。
- 不上传薪资。
- 不做隐藏追踪。
- 不强制账号。
- 提供一键清空本地数据。

## 9. 轻角色与文案

MVP 做轻角色，不做重桌宠。

轻角色能力：

- 状态：开工、摸鱼、午休、快下班、加班低电量、收工。
- 动画：呼吸、眨眼、伸懒腰、偷笑、挥手。
- 出现位置：主面板、可选悬浮小窗、提醒、分享图。
- 原则：角色服务情绪，不抢“工资在跑”的主体验。

文案调性：

- 常驻：温和、低打扰。
- 触发：有梗、办公室安全、自嘲。
- 分享：更强数据感和赛博感。

示例：

- “今天已经回血一截了。”
- “老板不在，收入照来。”
- “这不是走神，是现金流管理。”
- “CASHFLOW ONLINE.”

## 10. 提醒与成就

提醒要有陪伴感，不要像健康管理或工作监督。

MVP 提醒：

- 上班开工。
- 午休开始/结束。
- 快下班。
- 喝水。
- 站立。
- 上厕所。
- 眨眼。
- 长时间摸鱼轻调侃。

控制原则：

- 默认低频。
- 所有提醒都可关闭。
- 支持勿扰时段。
- 不连续弹窗刷屏。

本地成就：

- 连续回血。
- 准点下班。
- 午休守护者。
- 摸鱼回血。
- 工位续命。

成就只保存在本地，MVP 不做排行榜。

## 11. 分享设计

MVP 三个模板：

1. 今日打工战报：今日已赚、每秒到账、打工进度、下班倒计时。
2. 摸鱼回血账单：摸鱼时长、摸鱼收益、摸鱼占比、调侃文案。
3. 下班生存卡：距离下班、今日已熬过、今日回血、轻鼓励或吐槽。

用户可配置：

- 主题。
- 随机文案。
- 隐私显示模式。
- 保存图片。
- 复制图片。
- 弱引流标识。

分享图不要强广告化。默认只在角落放小产品名或短链接。二维码、强口号和大水印后续通过测试决定。

## 12. 技术架构

硬目标：**体积小、资源占用少、常驻稳定**。

推荐技术栈：

- Tauri 2 作为桌面壳。
- Web 前端实现 UI。
- Rust/native 层处理桌面集成。
- 本地键值存储保存设置。
- 只有用户开启本地统计时，才使用更结构化的本地数据。

选择 Tauri 的原因：

- 比 Electron 更适合常驻轻工具。
- 官方能力覆盖托盘、开机自启、通知、本地存储、窗口状态等关键需求。
- Windows 使用 WebView2。Windows 11 自带 WebView2，旧系统可由安装器处理运行时。

模块划分：

- 计算核心：纯规则、可测试、可复用。
- 状态调度：时间节点、手动覆盖、跨天、睡眠唤醒。
- 本地数据：设置、隐私、提醒、本地统计。
- 桌面集成：托盘、通知、开机自启、窗口、剪贴板。
- 表现层：主面板、设置、角色、主题、文案。
- 分享渲染：按需在本地生成图片。

轻量约束：

- 除非 Tauri 阻塞核心需求，否则不切 Electron。
- 不使用重型 3D、视频、大体积图片包、复杂粒子。
- 角色优先使用 SVG、CSS 动画、小尺寸位图序列或轻量矢量动画。
- 后台不跑重任务。
- 使用轻量定时器，只重算必要数据。
- 分享图按需生成，不后台预渲染。
- 本地日志最小化。
- MVP 不做更新检查，维持离线优先。

初步资源预算：

- 客户端安装包目标：在不内置 WebView2 离线运行时的情况下，尽量控制在 30MB 以内。
- 常驻内存目标：公开 Beta 前以 100MB 以下为目标，越低越好。
- 空闲 CPU：接近 0，不能持续占用明显 CPU。
- 冷启动：目标 2 秒内打开主面板。
- 这些数字需要通过技术 spike 验证，不能在未实测前作为市场承诺。

## 13. 分发策略

MVP 分发：

- 先做小范围内测包。
- 公开 Beta 通过官网落地页下载。
- 首发不依赖 Microsoft Store。

正式发布前需要：

- 选择安装包或便携包策略。
- 代码签名方案。
- SmartScreen 声誉处理。
- 官网明确隐私承诺。
- FAQ 覆盖安装、开机自启、托盘隐藏、杀软误报。
- 反馈表或用户群。

重点测试：

- Windows 10 和 Windows 11。
- 不同显示缩放。
- 多显示器。
- 睡眠唤醒。
- 跨天重置。
- 系统时间变化。
- 托盘隐藏区。
- 通知权限。
- 开机自启。
- 低权限办公电脑。
- 离线安装和离线使用。

## 16. 变现路径

MVP 完全免费。

验证阶段不加付费墙、不加付费弹窗、不强制账号、不做订阅。目标是先验证留存、传播和推荐意愿。

预留变现点：

- 主题包。
- 文案包。
- 分享模板包。
- Pro 买断。
- 无水印或自定义水印。
- 本地报告。
- 多工作配置。
- 高级隐私模式。
- 更多角色状态。

订阅会员不是第一优先。只有当后续出现持续云服务、持续主题更新、账号同步或付费内容更新时，订阅才合理。

## 17. 验证指标

由于 MVP 离线优先、无强制账号、无默认埋点，指标必须按可采集性分层。

### 可直接采集

这些指标发生在客户端外部，可以直接统计：

- 官网访问量。
- 下载按钮点击量。
- 安装包下载量。
- 不同渠道链接访问量。
- H5 计算器使用量。
- H5 分享图生成次数。
- H5 到下载页转化率。
- 反馈表提交量。
- 用户群加入量。
- 内容平台收藏、评论、转发、私信咨询。

### 内测授权采集

这些指标必须依赖用户同意、问卷、访谈或用户主动导出匿名摘要：

- 7 天后是否仍在使用。
- 是否开启开机自启。
- 每天大概常驻多久。
- 是否生成过分享图。
- 是否真的发给同事或朋友。
- 哪类提醒有用而不是烦。
- 哪类文案好笑而不是尴尬。
- 是否愿意为主题或 Pro 付费。

### 客户端本地展示

这些数据可以给用户自己看，但默认不上报：

- 今日活跃时长。
- 近 7/30 天使用天数。
- 分享图生成次数。
- 摸鱼状态次数。
- 提醒触发次数。
- 本地成就进度。

正确的 MVP 验证方式是：公开版看外部增长和反馈，内测阶段用授权数据验证留存，客户端行为数据默认只留在本地，除非用户主动导出。

## 18. 待决策项

这些不是缺失需求，而是进入实现计划前需要单独收敛的决策：

- 最终产品名。
- 默认角色视觉形态。
- 公开 Beta 是否包含悬浮小窗。
- 安装包格式和代码签名供应商。
- 技术 spike 后确认精确体积和内存预算。
- 官网域名和分享图弱引流样式。
- 第一批 20-50 个种子用户招募渠道。
